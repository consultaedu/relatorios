## O que este arquivo esclarece

`apiCarregarBase_` (169–438) lê `BASE_DASHBOARD`. `MINUTOS_GRAVADOS` → `minutosGravados` (295–298 / 394–395), `DURACAO_PREVISTA_MIN` → `duracaoPrevista` (301–304 / 397–398), `COBERTURA` → `cobertura` (307–310 / 400–401). Não calcula esses valores a partir de gravações ou datas. `chaveSessao` prefere `CHAVE_SESSAO_GLOBAL`, depois `CHAVE_GLOBAL` (326–331); faltam as regras que criam essas chaves.

Portanto, agora foi confirmado o mapeamento dos campos da API. **Continuam ausentes a importação/consolidação semanal, as fórmulas das colunas e a ligação entre o relatório individual e a base geral.** Não foram inferidos fórmula/limite de `COBERTURA`, geração de duração ou completude de intervalos nas demais contas.

A API calcula um resumo, incluindo a média simples de `cobertura` (709–716 / 781–788). O frontend original também calculava média simples a partir das linhas. O frontend corrigido recalcula indicadores de `dados` e não usa `resumo.coberturaMedia`, portanto o novo indicador depende de corrigir o frontend, além de preservar qualidade dos dados na API.

Não há rotina de importação nem gatilho semanal nesse arquivo. A periodicidade semanal foi informada pelo usuário; não foi verificada na implantação. Atualizar no dashboard/bypassar o Worker não importa dados das planilhas individuais. O caminho é:

```text
contas individuais → consolidação semanal → BASE_DASHBOARD
→ doGet → Worker → dashboard
```
